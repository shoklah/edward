# Usage % in place of dollars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store the reporter's `all_pct`/`fable_pct` usage estimates and show them, all-models first and Fable one step away, wherever a task or a week is measured, in place of dollars.

**Architecture:** The schema declares the unit-level estimates and `totals.usage`; `mergeKnown` replaces them with each transcript read. One helper in `facts.ts` sums units' estimates (known only, plus a not-estimated count); the views use it for weeks (runs and sessions), changes and goals. Weeks also passes the reporter's calibration through `reporterTotals`. The web screens swap their cost cells for the estimates; Spend, phases, Steps, agents and Models keep dollars.

**Tech Stack:** TypeScript, zod, Hono, Drizzle/SQLite, React, TanStack Query, Tailwind/shadcn, ECharts, Vitest, Storybook, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-20-usage-pct-design.md` (approved mockups in `docs/design/2026-11-20-usage-pct/`).

## Global Constraints

- Unknown is null and shows as `Unknown`'s dash, never 0; a known 0 shows "0.0" (muted by `Num`).
- A total adds the known values only and carries `notEstimated`: the units whose `all_pct` or `fable_pct` is null.
- A week's estimate covers its runs and its sessions (each placed by `unitWeeks`); `weekSums`' other sums stay runs only.
- A session's estimate is its own part only; its held runs carry the rest.
- Table cells: one decimal, plain under a header naming the unit ("All models (%)"); a known value above 0 and under 0.05 shows "<0.1". Prose, tiles and facts add "%".
- Dollars stay on Spend, the run page's phases and agents, Steps, Models. Weeks loses its "Usage (points)" group.
- Borrowed marker: muted lucide `History`, `aria-hidden`, in a focusable tooltip trigger named "Rates borrowed from the week of <week>" (week through `weekLabel`), before the value; Weeks only.
- Not-estimated marker: muted lucide `CircleAlert`, same pattern, named "N units not estimated" ("1 unit not estimated"); Work's goal sections only.
- Usage estimates: Weeks only, the Period's weeks, newest first, ignoring path/project filters and the scope, marked with `ReporterMark`.
- Code conventions in `CLAUDE.md` hold throughout (pure views, `reporterTotals`, `addKnown`, `Num`, `DataList`, `Pairs`, `Panel`, format helpers in `format.ts`, stories for empty and full states).

## Review Focus

1. **An export from before this change** (no `all_pct`, no `totals.usage`): every estimate cell is the dash, every count counts every unit, Usage estimates shows "No usage estimates in this export.", no page crashes. Pinned in Tasks 3, 4 and 6.
2. **A re-import whose estimate became null**: the stored value is replaced by null, not kept. Pinned in Task 1.
3. **Showing mode**: sums still count hidden projects' units; Usage estimates and the borrowed markers leak no project name (`leaks`). Pinned in Tasks 3 and 4.
4. **A path filter on Weeks**: sessions drop out of the week sums (as `periodUnits` does), so the numbers equal the runs-only ones. Pinned in Task 3.
5. **A week where only Fable or only all-models borrowed**: only that limit's cell carries the marker, and only that group's "From" is filled. Pinned in Tasks 3 and 6.
