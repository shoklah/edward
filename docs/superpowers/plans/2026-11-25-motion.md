# Motion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Edward moves as liquid glass: pages wash away, what arrives condenses, what an import changes ripples, what moves flows, and a test keeps every other motion out.

**Architecture:** One folder, `packages/web/src/motion/`, holds the only `Element.animate` call, the springs, one WebGL2 light canvas and two SVG filters. The rest of the app reaches it through four verbs and the hooks that notice a change. Motion plays only *from* somewhere to the DOM's own state, so nothing waits for it and every test that isn't about motion runs under reduced motion.

**Tech Stack:** React 19, TanStack Router and Query, CSS, the Web Animations API, SVG filters, WebGL2, Vitest in chromium, Storybook, Playwright. No dependency is added.

**Spec:** `docs/superpowers/specs/2026-11-25-motion-design.md`. The mockup, `docs/design/2026-11-25-motion/` (`liquid.js`, `surface.js`, `motion.js`, `motion.css`, preset **Wash**), is the reference for the shader, the maps and every number this plan quotes; port its code, don't reinvent it. Its other presets (Drip, Drain, Mercury) are not built.

**Kits:** `ui [react-tailwind-shadcn]`, tag motion, on tasks 1 and 3 to 9.

## Global Constraints

- No dependency. No generated file (`src/components/ui/`) is edited. No new screen, layout or text.
- Every animation goes through `play` (Task 1) and carries its verb as its `id`. Motion animates `transform` and `opacity`, plus `stroke-dashoffset` on the run graph's lines; a keyframe may hold another property at one fixed value (`transformOrigin`, `strokeDasharray`, `markerEnd`), never move it.
- Every entry point asks `motionRuns()` first and otherwise does nothing. The DOM is in its final state from the commit.
- Nothing carries a `backdrop-filter`. At most one element is drawn through a filter, only while a wave runs. The live page's bend ends at the first scroll; the wash's copy ignores scrolls.
- No motion makes anything scroll, in the page or in a list, or a list's edge fade: no row springs past its list's end, and a drop's glass stays inside its cell, whatever the number's width.
- Never moves: charts, hover, focus, the backdrop, filters, paging, closing a row, deselecting a box, switching a view or measure, loading and error states, showing mode, account switching, sign out.
- Times, from the spec: front 900 ms; block 640 (opaque at 190); title 620; graph about 1200; pill, ring and detail 420; import front 2000, over by 2300; number 2600; arrival 680; small ripple 1300 over 110 px; blink 260; row 480; sort 520, 18 apart; seen item 260, 34 apart; thumb 160; dialog and tooltip 200, a closing dialog 120.
- Under 768 px: no copy, cut or bend. Outside Chromium (no `navigator.userAgentData`): no bend, the copy cut by a `clip-path`.
- An inert copy's layer is `data-copy="page"`, `"items"` or `"prepare"`, fixed, `aria-hidden`, `inert`, `pointer-events: none`.
- `DESIGN.md` and the root `CLAUDE.md` hold: relative imports with `.ts`, a story per component's state, colours only as tokens in `index.css` in both modes.
- Screens' baselines don't change. Any that differ are a defect, except the selected box's ring (Task 5).
- e2e: `E2E_PORT=<free port> pnpm --filter @cwd/web exec playwright test --project=checks --project=checks-dark <files>`; the server takes the next port too. Unit tests and stories: `pnpm vitest run <files>`. Screens: `pnpm test:screens` (Docker).
- Each task's convention lines go under `## Code conventions` in the root `CLAUDE.md` in its commit; in Wave A they go in the report's `Conventions:` block.
- Every task ends with `pnpm -r typecheck`, its tests green, and one commit.

## Review Focus

1. A page pressed away from while its filter select, checkbox or sideways-scrolled table isn't in its default state: the copy shows what the reader was looking at. (Task 3)
2. Home reached by a press: React Flow measures its boxes while the panel is scaled, and would keep its edges off their boxes; they end as on a first load. (Task 3)
3. The WebGL context lost while a wave runs: the light ends, the page and later waves are unharmed, nothing is logged as an error. (Task 2)
4. A second import changing a number still inside its drop: the newest number shows, with nothing left over. (Task 7)

## File Structure

| File (`packages/web/src/motion/`) | Responsibility |
|---|---|
| `index.ts` | The only file the app imports: verbs (`wash`, `condense`, `ripple`, `flow`), `use*` hooks, and `motionRuns` for the one scroll that isn't an animation |
| `play.ts` | Whether motion runs, springs, the one `Element.animate` |
| `place.ts` | Rectangles: in the window, centre, reach, the import's and the press's source |
| `water.ts` | The WebGL2 canvas: light only |
| `Filters.tsx` | The two SVG filters and their maps |
| `bend.ts` | Running a filter, or the clip-path cut, along a front |
| `condense.ts` | What arrives |
| `wash.ts` | The page switch; copies; Mark all seen's copies |
| `flow.ts` | Travelling between two places, moved rows, the chevron, the pill |
| `draw.ts` | The run graph drawing itself |
| `ripple.ts`, `Drop.tsx` | What an import changed, the import wave, the number's drop |

Tests sit beside them. `src/test/motion.ts` turns motion on in a story or a unit test; `e2e/motion.ts` and `e2e/motion.spec.ts` in the browser.
